# StayEase — Hotel Room Booking System

An ASP.NET Core MVC starter implementation for a small hotel. Guests can search rooms, submit bookings, receive a confirmation, and look up/cancel bookings by email. Staff can sign in to manage rooms and booking statuses.

## Technology stack
- ASP.NET Core MVC, C# (.NET 8)
- SQL Server with Entity Framework Core
- ASP.NET Core Identity (cookie authentication and Admin role)
- Razor Views, Bootstrap 5, custom responsive CSS

## Features included
- Responsive room listing and date/guest search
- Room details and nightly pricing
- Booking form, server-side validation and total calculation
- Overlap check for active bookings
- Booking confirmation and lookup by email
- Guest cancellation before check-in
- Staff login, room create/edit, booking dashboard and status updates
- Sample rooms seeded on first launch

## Run locally
Prerequisites: .NET 8 SDK and SQL Server LocalDB (included with many Visual Studio installations), or a SQL Server instance.

1. Open `src/HotelBookingSystem.sln` in Visual Studio, or open a terminal in `src/HotelBookingSystem`.
2. Check `appsettings.json`. The default connection uses LocalDB:
   `Server=(localdb)\\MSSQLLocalDB;Database=HotelBookingDB;Trusted_Connection=True;MultipleActiveResultSets=true;TrustServerCertificate=True`
3. Run the app:
   ```bash
   dotnet restore
   dotnet run
   ```
4. Open the local URL printed in the terminal. On first run the app creates its database and seeds three rooms and a staff account.
5. If LocalDB is not installed, update the connection string to point to your SQL Server instance and ensure the account has permission to create the database.

## Design decisions
- **Guest booking without mandatory registration:** lowers friction for a small hotel demo; guests retrieve reservations using the email used at booking.
- **Room and Booking entities:** keeps the core data model small and easy to explain.
- **Date overlap rule:** two stays overlap when `requestedCheckIn < existingCheckOut` and `requestedCheckOut > existingCheckIn`. Cancelled bookings do not block availability.
- **Total price:** number of nights multiplied by the room's current nightly price.
- **Staff role:** ASP.NET Core Identity protects the admin dashboard and room management.
- **What I would add with more time:** transaction/locking strategy to eliminate race conditions under simultaneous bookings, email notifications, payment gateway, audit log, pagination, automated tests, richer room photos, and full EF Core migrations.

## Known issues / review before submission
- This is a starter implementation, not a production-hardened booking platform.
- Booking lookup and cancellation use email as a lightweight demo flow; production should verify ownership with a secure token or authenticated guest account.
- A simultaneous double booking can still occur between availability check and save; implement a transaction/locking or reservation strategy before production.
- `EnsureCreated` is used to simplify first-run setup. For long-term maintenance, replace it with EF Core migrations.
- The standalone SQL script contains the business tables and sample rooms; Identity schema is created by the app. The `.bak` backup must be generated on SQL Server.
- Bootstrap and validation scripts use CDN links, so an internet connection is needed for those assets.
- Automated build and browser verification must be performed on your machine before submitting.
